# Практическая работа: GitHub Actions, Self-Hosted Runner и Docker Compose

## Что реализовано
- GitHub Actions workflow запускается при `push` в `main` и вручную.
- Workflow выполняется на `self-hosted` runner.
- Создаёт `.env` из GitHub Secrets.
- Запускает веб-приложение и PostgreSQL через `docker-compose up -d`.
- Проверяет контейнеры, доступность приложения и совпадение количества записей в БД и API.
- Сохраняет отчёт и диагностические файлы как GitHub Actions artifacts.

## 1. Подготовка репозитория
1. Создайте пустой репозиторий GitHub.
2. Распакуйте архив и загрузите в репозиторий всё содержимое папки.
3. Основная ветка должна называться `main`.

## 2. Добавление GitHub Secrets
Откройте `Settings → Secrets and variables → Actions → New repository secret` и создайте:

| Имя | Значение для примера |
|---|---|
| DB_HOST | db |
| DB_PORT | 5432 |
| DB_NAME | myapp |
| DB_USER | app_user |
| DB_PASSWORD | задайте свой пароль |
| APP_PORT | 3000 |
| APP_SECRET | задайте длинную случайную строку |
| API_KEY | задайте произвольный тестовый ключ |

Не публикуйте реальные пароли и токены. Значения в таблице — учебные, пароль и секреты лучше заменить своими.

## 3. Установка Self-Hosted Runner
На компьютере/сервере, который будет выполнять workflow:
1. Установите Docker и Docker Compose (команда `docker-compose` должна работать).
2. В репозитории откройте `Settings → Actions → Runners → New self-hosted runner`.
3. Выберите ОС и архитектуру.
4. Выполните на своём компьютере команды установки и регистрации, которые покажет GitHub. Не передавайте регистрационный токен другим лицам.
5. Запустите runner командой, указанной GitHub (обычно `./run.sh`).
6. Убедитесь, что в настройках репозитория статус runner — `Online`.

Для постоянной работы runner можно установить как службу по инструкции GitHub.

## 4. Запуск
Сделайте commit и push в `main`. Либо откройте вкладку `Actions`, выберите workflow `Full Stack Application Deployment Test` и нажмите `Run workflow`.

## 5. Проверка результата
В `Actions` откройте запуск workflow:
- все шаги должны завершиться зелёным статусом;
- в логах должен появиться результат проверки приложения и БД;
- в разделе `Artifacts` скачайте `deployment-artifacts` и `docker-logs`.

На машине runner можно проверить контейнеры командой:
```bash
docker-compose ps
```
Ожидаемый статус сервисов — `Up`/`running`.

Приложение после запуска доступно на `http://localhost:3000`.

## 6. Важные замечания
- Workflow рассчитан на Linux self-hosted runner с установленными Docker и Docker Compose.
- Для `self-hosted` runner используйте только доверенный репозиторий и проверенные изменения: такой runner может иметь доступ к локальной машине.
- В артефакты попадает только замаскированный `.env` без значений секретов. Настоящий `.env` не загружается.
- Это учебное демонстрационное приложение. Для реального production-развёртывания нужны дополнительные настройки безопасности.
